# Local GitHub Repository Code Explainer using a Local LLM

## 1. Project Objective

This application explains the contents of any public GitHub repository, including source code, READMEs, PDFs, data/configuration files, and binary/special-file metadata. GitPython fetches Git objects without checking out paths, so Windows-invalid names do not block analysis.

The repository code and prompts are sent to the Ollama server on this computer. The application does not use a paid cloud LLM API.

## 2. Problem Statement

Beginners often find it difficult to understand how an unfamiliar code repository is organized and how its important files work together. This project collects a limited amount of source code from a public GitHub repository and asks a local language model to explain it in simple terms.

## 3. Features

- Accepts a public GitHub repository URL.
- Fetches the repository with GitPython without checking out files to disk.
- Skips dependency, build, editor, cache, and coverage folders.
- Prioritizes application files over tests, benchmarks, documentation, and CI files.
- Reads supported source files, documentation, data/configuration, and dependency manifests.
- Extracts bounded PDF text with pypdf; identifies PBIX and other binary files by metadata without pretending to inspect their internals.
- Scans supported files locally for imports, functions, classes, constants, and code size.
- Sends one bounded repository context and selected source code to Qwen in a single request.
- Generates a beginner-friendly explanation dynamically with Qwen 2.5 3B through Ollama.
- Reports found files, analyzed files, skipped files, and analysis limits.
- Returns the result from FastAPI and displays it in Streamlit.
- Removes the temporary clone after the request finishes.

## 4. Technologies Used

## 5. System Architecture

```text
User
  -> Streamlit frontend
  -> FastAPI backend
  -> GitPython fetches Git objects without a working-tree checkout
  -> All tracked files are inventoried by path and type
  -> README/PDF/data text and source structure are extracted locally
  -> Important source files and collected context are sent in one bounded Qwen request
  -> FastAPI returns the generated explanation
  -> Streamlit displays it to the user
```

## 7. Installation

Open PowerShell in the project folder. Create a virtual environment if you do not already have one, then activate it:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install the Python packages:

```powershell
python -m pip install -r requirements.txt
```

Git must also be installed and available on your PATH because GitPython uses the Git command-line program to clone repositories. Check it with:

```powershell
git --version
```

## 8. Install and Run Ollama

1. Install Ollama for Windows from [ollama.com](https://ollama.com/).
2. Start the Ollama application. It normally runs its local service in the background.
3. In PowerShell, download the required model:

```powershell
ollama pull qwen2.5:3b
```

4. Confirm that the model is installed:

```powershell
ollama list
```

The backend calls Ollama at `http://localhost:11434/api/generate`.

## 9. Test the Ollama Connection

With Ollama running and the model downloaded, run:

```powershell
python test_ollama.py
```

A successful test prints a response generated by `qwen2.5:3b`. If it cannot connect, start Ollama. If Ollama reports that the model is missing, run `ollama pull qwen2.5:3b`.

## 10. Start FastAPI

From the project root, start the backend:

```powershell
uvicorn backend.main:app --reload
```

Keep this terminal open. The `backend.main:app` import path means: load the `app` object from `main.py` inside the `backend` folder.

## 11. Open the API Documentation

Open [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) in a browser. The interactive page is generated by FastAPI. Expand `POST /explain`, choose **Try it out**, and submit a request such as:

```json
{
  "github_url": "https://github.com/pallets/flask"
}
```

A successful response contains `success`, `repository_url`, `repository_type`, `files_found`, `files_analyzed`, `files_analyzed_deeply`, `files_summarized`, `files_skipped`, `file_type_summary`, `analyzed_files`, `summarized_files`, `skipped_files`, `analysis_notes`, `ollama_requests`, `total_analysis_time_seconds`, and `explanation`.

The explanation includes repository type and structure, technologies, important files, file-by-file source explanations when code exists, experiments/features, data flow, execution flow, data/dataset information, setup/usage, limitations, and a beginner-friendly summary. Source-free repositories receive document- and metadata-based explanations without invented functions/classes.

## 12. Start Streamlit

Open another PowerShell terminal in the project root, activate the same virtual environment, and run:

```powershell
streamlit run frontend/app.py
```

Streamlit prints the local page address in the terminal and usually opens it in a browser automatically.

## 13. How the Application Works

1. The user enters a GitHub URL in Streamlit.
2. Streamlit sends the URL as JSON to FastAPI's `POST /explain` endpoint.
3. Pydantic checks that the request contains a valid HTTP or HTTPS URL.
4. GitPython fetches the public Git repository without checking out files; the backend reads committed Git blobs directly.
5. The repository processor inventories all tracked paths and classifies source, docs, data, PDFs, Power BI files, and other file types.
6. README/document/data/source text is read locally. pypdf extracts bounded text from PDFs. PBIX internals are not opened.
7. Python AST and simple text patterns extract local source structure; up to 8 important source files are selected within a 6,000-character code budget.
8. One Qwen request receives the collected context and selected code and generates the repository and file explanations.
9. FastAPI returns repository/file-type metadata and the explanation. The temporary Git object database is closed and removed even after errors.

## 14. Example Usage

1. Start Ollama and confirm that `qwen2.5:3b` is installed.
2. Start FastAPI and Streamlit in separate terminals.
3. Enter `https://github.com/pallets/markupsafe` or `https://github.com/prakruthidevanga/Business-Analytics` in Streamlit.
4. Select **Explain This Repository** and wait for the single local Qwen request.
5. Review the repository type, file counts/types, extracted documentation, source explanations when present, and file limitations.

## 15. Limitations

- Only public GitHub repositories can be cloned; private repository authentication is not included.
- Git tree inspection reads tracked blobs without checking out repository paths, so paths that Windows cannot create are still inventoried and read safely.
- Source/config text files over 100 KB are skipped. At most 8 prioritized source files and 6,000 source characters are sent to Qwen; selected files are individually capped at 4,000 characters.
- Every supported README/PDF/data/source file is inspected locally within a 7,000-character shared document-text budget. Each PDF is limited to 8 MB, 12 pages, and 700 extracted characters.
- The application makes one Ollama request per repository. Remaining source is summarized from local structure; PDFs are represented by bounded text excerpts; PBIX and other binary internals are not inspected.
- Large repositories may have lower-priority files summarized only by path/type/structure. The API lists deeply analyzed, summarized, skipped, and metadata-only files.
- Local model output can still be incomplete or inaccurate. Prompts request source evidence and explicitly mark unclear facts, but Qwen cannot guarantee zero hallucinations. Check important details against the listed source files.
- CPU-only local generation can still take time. The Ollama request timeout is 240 seconds and the frontend request timeout is 360 seconds; timeouts are shown as friendly API errors.
- Ollama must be running locally and the model must be downloaded. Generation speed depends on the computer's hardware.
- Cloning requires an internet connection and Git installed on the computer.
